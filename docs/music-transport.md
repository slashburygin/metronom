# Музыкальная модель и транспорт

Модель композиции и транспорт разделяют музыкальное время и секунды аудиоустройства. Метроном уже использует этот транспорт; генератор аккомпанемента подключается к тем же событиям следующим этапом.

## Музыкальное время

`musical-time.js` хранит длительности целыми дробями `{ n, d }` в целых нотах. Например, четверть — `fraction(1, 4)`, четверть с точкой — `fraction(3, 8)`, триольная восьмая — `fraction(1, 12)`. Дроби сокращаются, сериализуются в JSON, а некорректные значения и переполнение безопасных целых отклоняются.

`secondsFor(duration, bpm, tempoUnit)` переводит длительность в секунды только на границе с аудиодвижком. При 120 BPM четвертями длительность 3/8 равна 0,75 секунды; при 120 BPM четвертями с точкой — 0,5 секунды.

В самостоятельном метрономе BPM относится к выбранной в знаменателе ноте: смена 4/4 на 4/8 сохраняет число кликов в минуту. У композиции `tempoUnit` задаётся независимо от размера; по умолчанию это четверть.

## Композиция

`compileSong(input)` проверяет и нормализует иерархию композиция → секции → такты → аккорды и возвращает `{ song, steps, duration }`. `song.version` равен 1. Каждый такт содержит собственный `meter`; автоматическое наследование размера от предыдущего такта не применяется. По умолчанию размер такта равен 4/4.

```js
import { fraction as f } from '../site/src/musical-time.js';
import { compileSong } from '../site/src/song.js';

const compiled = compileSong({
  title: 'Каденция',
  key: 'C',
  bpm: 120,
  tempoUnit: f(1, 4),
  sections: [{
    name: 'A',
    measures: [{
      meter: { numerator: 4, denominator: 4 },
      chords: [
        { symbol: 'Dm7', offset: f(0), duration: f(1, 2) },
        { symbol: 'G7', offset: f(1, 2), duration: f(1, 2) },
      ],
    }, {
      meter: { numerator: 6, denominator: 8, groups: [3, 3] },
      chords: [{ symbol: 'Cmaj7', offset: f(0), duration: f(3, 4) }],
    }],
  }],
});
```

`groups` определяет пульс: 6/8 по умолчанию состоит из двух групп по три восьмых. Для 5/8 можно задать `[2, 3]`, для шести отдельных восьмых — `[1, 1, 1, 1, 1, 1]`. Группы должны в сумме давать числитель размера.

Символ аккорда пока сохраняется как строка. Позиция и длительность обязательны; аккорд не может выходить за такт или пересекаться с другим аккордом. Пробелы между аккордовыми событиями не создают новых событий; генератор должен завершать каждую ноту по её длительности. Отдельные правила N.C., парсер аккордов и сложные повторения будут добавлены последующими этапами.

`steps` — линейные пульсы с точной позицией и длительностью, индексами секции, такта и доли. События `click` и `chord` имеют точное смещение внутри пульса; смена аккорда может приходиться между кликами. Исходный ввод не изменяется.

## Транспорт

```js
import { Transport } from '../site/src/transport.js';

const transport = new Transport({
  context: audioContext,
  steps: compiled.steps,
  bpm: compiled.song.bpm,
  tempoUnit: compiled.song.tempoUnit,
  onSchedule(event, timing) {
    // Все партии используют timing.time — будущую отметку AudioContext.
    // Создать источник и начать его в timing.time, затем зарегистрировать:
    // transport.track(source, cleanup, timing.time + timing.duration);
  },
  onEvent(event, timing) {
    // Обновить подсветку, когда событие достигнет аудиочасов.
  },
});

await transport.start();
```

Вместо массива `steps` можно передать чистую функцию `nextStep(index)`, возвращающую пульс либо `null` в конце последовательности. Этот вариант использует бесконечный метроном. Функция может вызываться повторно для проверки границ и должна быть без побочных эффектов. Пульсы должны иметь положительную длительность, события — упорядоченные смещения внутри пульса; `compileSong` формирует такие данные.

- `start({ index, countIn })` запускает с индекса пульса. `countIn` — массив подготовленных пульсов; из них исполняются только события `click`.
- `setLoop(start, end)` задаёт диапазон пульсов `[start, end)`. Конец не включён; `setLoop(null)` отключает цикл. На переходе к началу цикла источники предыдущего прохода завершаются по аудиочасам. Задавать цикл следует до старта: уже запланированные события при смене диапазона не переносятся.
- `seek(index)` отменяет активные и будущие источники, очищает визуальную очередь, убирает отсчёт и продолжает с новой позиции с небольшим стартовым запасом.
- `stop()` также отменяет незавершённый `AudioContext.resume()`. Поздний ответ старого запуска не может перезапустить транспорт.
- Повторный `start()` начинается с последней явно выбранной стартовой позиции, а не с опережающего курсора планировщика.
- `setBpm()` меняет длительность следующих ещё не запланированных пульсов. Уже поставленные отметки времени сохраняются. Непрерывные темповые кривые пока не поддерживаются.
- `position()` возвращает текущий пульс и долю его прохождения по аудиочасам. До первого услышанного пульса и после остановки возвращается `null`.
- `dispose()` останавливает воспроизведение и завершает Worker.

Worker будит планировщик каждые 25 мс; тот готовит пульсы, начинающиеся в ближайшие 100 мс, вместе с их событиями. Визуальная очередь обрабатывается через requestAnimationFrame. Точность звука не зависит от частоты перерисовки; ограничения фонового аудио мобильных браузеров требуют отдельной проверки.

Каждый источник нужно зарегистрировать через `track(source, cleanup, stopAt)`. Транспорт сам назначает окончание источника и сокращает его до границы таймера или конца композиции. `cleanup` освобождает узлы графа после `ended` либо немедленно при остановке/перемотке. Повторная очистка исключена. Для бесконечного источника можно не задавать `stopAt`; его остановит транспорт.

Таймер задаётся функцией `durationSeconds`, возвращающей длительность занятия в секундах; 0 отключает ограничение. Отсчёт входит в длительность занятия. Перемотка не обнуляет таймер. Завершение конечной композиции и таймера вызывает `onStop`, ручная остановка — нет.

## Основания и проверки

Существующий контракт метронома изучен в репозитории `metronom`, коммит `9a12326`, `site/src/metronome.js:43`: планирование по AudioContext и отдельная очередь визуальных событий сохранены при выделении транспорта.

Upstream-ориентир — [Tonejs/Tone.js](https://github.com/Tonejs/Tone.js), MIT, pin `28a689c4a80c3b840b9e08e457285584e09f9d5f`, `Tone/core/clock/Transport.ts:239` (`_processTick`) и `Tone/core/clock/Clock.ts:289` (`_loop`). Изучены разделение музыкального курсора и аудиовремени и проверка границы цикла перед исполнением события. Исходники найдены через локальный корпус XERJ `metronom-audio`; Tone.js не установлен как зависимость, реализация транспорта собственная.

Тесты `song.test.js` и `transport.test.js` проверяют точные дроби, JSON, переполнение, размеры и группировки, границы аккордов, единые отметки звука и подсветки, отсчёт, циклы, смену BPM, таймер, остановку и перемотку, завершение источников и гонку асинхронного запуска.
