# Музыкальная модель и транспорт

Модель композиции и транспорт разделяют музыкальное время и секунды аудиоустройства. Метроном и аккомпанемент используют общий транспорт и жизненный цикл аудиоисточников.

## Музыкальное время

`musical-time.js` хранит длительности целыми дробями `{ n, d }` в целых нотах. Например, четверть — `fraction(1, 4)`, четверть с точкой — `fraction(3, 8)`, триольная восьмая — `fraction(1, 12)`. Дроби сокращаются, сериализуются в JSON, а некорректные значения и переполнение безопасных целых отклоняются.

`secondsFor(duration, bpm, tempoUnit)` переводит длительность в секунды только на границе с аудиодвижком. При 120 BPM четвертями длительность 3/8 равна 0,75 секунды; при 120 BPM четвертями с точкой — 0,5 секунды.

В самостоятельном метрономе BPM относится к выбранной в знаменателе ноте: смена 4/4 на 4/8 сохраняет число кликов в минуту. У композиции `tempoUnit` задаётся независимо от размера; по умолчанию это четверть.

## Композиция

`compileSong(input)` проверяет и нормализует иерархию композиция → секции → такты → аккорды и возвращает `{ song, steps, duration, playOrder }`. `song.version` равен 1. Каждый такт содержит собственный `meter`; автоматическое наследование размера от предыдущего такта не применяется. По умолчанию размер такта равен 4/4.

```js
import { fraction as f } from '../site/src/musical-time.js';
import { compileSong } from '../site/src/song.js';

const compiled = compileSong({
  title: 'Каденция',
  key: 'C',
  bpm: 120,
  tempoUnit: f(1, 4),
  sections: [{
    name: 'A',
    measures: [{
      meter: { numerator: 4, denominator: 4 },
      chords: [
        { symbol: 'Dm7', offset: f(0), duration: f(1, 2) },
        { symbol: 'G7', offset: f(1, 2), duration: f(1, 2) },
      ],
    }, {
      meter: { numerator: 6, denominator: 8, groups: [3, 3] },
      chords: [{ symbol: 'Cmaj7', offset: f(0), duration: f(3, 4) }],
    }],
  }],
});
```

`groups` определяет пульс: 6/8 по умолчанию состоит из двух групп по три восьмых. Для 5/8 можно задать `[2, 3]`, для шести отдельных восьмых — `[1, 1, 1, 1, 1, 1]`. Группы должны в сумме давать числитель размера.

Символ аккорда пока сохраняется как строка. Позиция и длительность обязательны; аккорд не может выходить за такт или пересекаться с другим аккордом. Пробелы между аккордовыми событиями не создают новых событий; генератор должен завершать каждую ноту по её длительности. Аккорды и паузы интерпретирует `chords.js`, а повторения и переходы проверяет `song-form.js`.

`steps` — линейные пульсы с точной позицией и длительностью, индексами секции, такта и доли. События `click` и `chord` имеют точное смещение внутри пульса; смена аккорда может приходиться между кликами. Исходный ввод не изменяется.

## Развёртка формы

Нормализованный такт может содержать `form`: `{ repeatStart, repeatEnd, ending, endingEnd, segno, coda, fine, toCoda, jump }`. Флаги имеют тип boolean, `repeatEnd` — количество проходов 2–8, `ending` — массив номеров проходов, `jump` — `dc`, `ds`, `dc-fine`, `ds-fine`, `dc-coda` или `ds-coda`. Поле необязательно. Неизвестные поля и значения отклоняются.

`compileSong` сохраняет исходную сетку: `steps` и `duration` относятся к записанным тактам, `playOrder` — проверенный массив исходных `barIndex` в порядке исполнения. `expandSong(compiled)` из `song-form.js` создаёт звучащие пульсы с непрерывной точной позицией и `playbackBarIndex`, а `barIndex`, `sectionIndex` и `measureIndex` продолжают указывать на оригинал. Его `duration` соответствует всему звучащему маршруту. `arrangeSong` строит партии по расширенному маршруту, возвращая исходный `song` и исходные подписи `symbols`, расширенные `steps`/`duration` и `playOrder`.

`BackingPlayer` повторяет всю расширенную последовательность, поэтому тренировка меняет ключ/BPM после полного круга; отсчёт берёт только первый звучащий такт. Подсветка использует исходный `barIndex`, позиция в форме — `playbackBarIndex`. Подробные правила и ограничения: [редактор композиций](song-editor.md#репризы-и-переходы).

## Транспорт

```js
import { Transport } from '../site/src/transport.js';

const transport = new Transport({
  context: audioContext,
  steps: compiled.steps,
  bpm: compiled.song.bpm,
  tempoUnit: compiled.song.tempoUnit,
  onSchedule(event, timing) {
    // Все партии используют timing.time — будущую отметку AudioContext.
    // Создать источник и начать его в timing.time, затем зарегистрировать:
    // transport.track(source, cleanup, timing.time + timing.duration);
  },
  onEvent(event, timing) {
    // Обновить подсветку, когда событие достигнет аудиочасов.
  },
});

await transport.start();
```

Вместо массива `steps` можно передать чистую функцию `nextStep(index)`, возвращающую пульс либо `null` в конце последовательности. Этот вариант использует бесконечный метроном. Функция может вызываться повторно для проверки границ и должна быть без побочных эффектов. Пульсы должны иметь положительную длительность, события — упорядоченные смещения внутри пульса; `compileSong` формирует такие данные.

- `start({ index, countIn })` запускает с индекса пульса. `countIn` — массив подготовленных пульсов; из них исполняются только события `click`.
- `setLoop(start, end)` задаёт диапазон пульсов `[start, end)`. Конец не включён; `setLoop(null)` отключает цикл. На переходе к началу цикла источники предыдущего прохода завершаются по аудиочасам. Задавать цикл следует до старта: уже запланированные события при смене диапазона не переносятся.
- `seek(index)` отменяет активные и будущие источники, очищает визуальную очередь, убирает отсчёт и продолжает с новой позиции с небольшим стартовым запасом.
- `stop()` также отменяет незавершённый `AudioContext.resume()`. Поздний ответ старого запуска не может перезапустить транспорт.
- Повторный `start()` начинается с последней явно выбранной стартовой позиции, а не с опережающего курсора планировщика.
- `setBpm()` меняет длительность следующих ещё не запланированных пульсов. Уже поставленные отметки времени сохраняются. Непрерывные темповые кривые пока не поддерживаются.
- `position()` возвращает текущий пульс и долю его прохождения по аудиочасам. До первого услышанного пульса и после остановки возвращается `null`.
- `dispose()` останавливает воспроизведение и завершает Worker.

Worker будит планировщик каждые 25 мс; тот готовит пульсы, начинающиеся в ближайшие 100 мс, вместе с их событиями. Визуальная очередь обрабатывается через requestAnimationFrame. Точность звука не зависит от частоты перерисовки; ограничения фонового аудио мобильных браузеров требуют отдельной проверки.

Каждый источник нужно зарегистрировать через `track(source, cleanup, stopAt)`. Транспорт сам назначает окончание источника и сокращает его до границы таймера или конца композиции. `cleanup` освобождает узлы графа после `ended` либо немедленно при остановке/перемотке. Повторная очистка исключена. Для бесконечного источника можно не задавать `stopAt`; его остановит транспорт.

Таймер задаётся функцией `durationSeconds`, возвращающей длительность занятия в секундах; 0 отключает ограничение. Отсчёт входит в длительность занятия. Перемотка не обнуляет таймер. Завершение конечной композиции и таймера вызывает `onStop`, ручная остановка — нет.

## Аккомпанемент упражнений

`accompaniment.js` строит на основе `scaleHarmony` четыре такта каденции (ii, V, I, I) либо двенадцать тактов блюза. Мажорный блюз использует доминантсептаккорды I7, IV7 и V7; минорный — i7, iv7 и V7. Написание корней сохраняется, включая двойные знаки альтерации. Учебные формы используют тот же парсер аккордов и аранжировщик, что пользовательские композиции.

`buildAccompaniment(harmony, { form, style, seed })` возвращает скомпилированную композицию и события партий. Ровные восьмые делят четверть пополам, swing — в отношении 2:1. Общий аранжировщик поддерживает straight, swing, bossa nova, ballad и rock, голосоведение, walking bass и воспроизводимые вариации громкости по seed. Длительности партий не выходят за свои пульсы.

`BackingPlayer` исполняет эти события через общий `Transport`, создаёт отдельные GainNode для баса, клавиш и ударных и регистрирует каждый источник через `track`. Микшер работает во время воспроизведения. Отсчёт звучит отдельными кликами даже при отключённых партиях. Количество кругов реализовано конечным поставщиком пульсов; 0 означает игру до остановки. AudioContext передаётся из метронома, и интерфейс допускает только один активный проигрыватель.

Тембры синтезируются локально, без сэмплов и дополнительных npm-зависимостей. Шум ударных использует фиксированное начальное состояние генератора, чтобы offline-рендеры были воспроизводимыми. Голосоведение выбирается до планирования; профили тембров и реверберация описаны ниже.

При исследовании управления голосами прочитаны `Tone/instrument/PolySynth.ts:255` (`_triggerAttack`), `:278` (`_triggerRelease`) и `:298` (`_scheduleEvent`) того же pin Tone.js. Изучены раздельные голоса аккорда и их жизненный цикл; здесь используется собственная реализация с назначением аудиовремени непосредственно Web Audio и освобождением узлов через общий транспорт.

## Тембры и эффект комнаты

`BackingPlayer.start(compiled, { sound })` принимает `{ pianoTone, bassTone, reverb }`. Клавиши: `piano`, `electric`, `organ`; бас: `acoustic`, `electric`; уровень реверберации — число 0–1. `normalizeSound` проверяет сохранённые значения, ограничивает уровень и подставляет `piano/acoustic/0`. `setSound(sound)` меняет настройки с остановкой текущего воспроизведения; интерфейс также останавливает проигрыватель при изменении звука.

`backing-sound.js` задаёт спектры и огибающие. Клавиши складывают несколько гармоник, орган дольше сохраняет уровень, бас использует треугольную/пилообразную волну с фильтром низких частот. Каждая составляющая принадлежит общему транспорту и имеет конечную длительность; освобождение узлов выполняется после завершения всех источников голоса. Тембры синтезированные, внешние сэмплы и npm-зависимости не используются.

`backing-reverb.js` лениво создаёт стереофонический импульс длительностью 1,2 с с предзадержкой 15 мс: затухающий шум с фиксированным seed и нормированной энергией. Один буфер переиспользуется независимыми свёртками партий. Прямой звук идёт в GainNode партии, а параллельный путь — через ConvolverNode и гейт в тот же GainNode. Поэтому громкость/mute управляет и текущим сигналом, и хвостом. Уровень 0–100% означает интенсивность добавленного эффекта (коэффициент возврата до 0,45); прямой сигнал сохраняется. При нуле свёртки не создаются; отсчёт не проходит через них.

Аранжировщик добавляет события `silence` с точным смещением и списком партий: все партии для Break, бас/клавиши для N.C. и промежутков без гармонии. Гейт старой свёртки закрывается в аудиовремя начала паузы. Последующие ноты получают новую свёртку с тем же импульсом, поэтому старый хвост не появляется после паузы.

Транспорт сообщает границы через `onAudioClip(end)` и отмену через `onAudioCancel()`. Первый вызывается при ограничении аудио, включая loop, таймер и конечный маршрут; значение может быть Infinity. Эффект назначает нулевой уровень на конечной границе до UI-кадра. Второй вызывается после отмены источников при stop/seek/dispose и немедленно отключает узлы эффекта. Истёкшие свёртки освобождаются при дальнейшей обработке; остановка освобождает все. Музыкальные переходы внутри формы и автоматическая смена тональности между кругами сохраняют естественный хвост, пока воспроизведение продолжается.

## Дополнительные краски и сбивки

`arrangeSong(song, { style, seed, arrangement: { colors, fills } })` и `buildAccompaniment` принимают необязательные настройки аранжировки. `normalizeArrangement` принимает только boolean true, по умолчанию оба флажка выключены. Краски и рисунки выбираются независимыми детерминированными потоками, производными от общего seed; основной поток задаёт velocity.

`arrangement-ornaments.js` добавляет натуральную 9 к простым трезвучиям, 6/m6 и 7/maj7/m7, иногда также 13 к простому доминантсептаккорду. Добавляемые классы высот должны принадлежать исходной мажорной/натуральной минорной гамме. Например, G7 в C может получить A/E; в Cm эти добавления не допускаются. Явные расширения, альтерации, sus и уменьшённые качества возвращаются без изменений. Копия набора нот используется только при выборе расположения клавиш; бас вычисляется по исходному аккорду. Состав клавиш ограничен четырьмя голосами, поэтому основной тон и квинта могут опускаться. Сетка и символы остаются исходными; события добавленных нот помечены `color: true`, что сохраняется при транспонировании MIDI.

Сбивки учитывают `playOrder` и исходные индексы секций. Граница определяется как смена секции, несмежный исходный такт (реприза, вольта, D.C./D.S./Coda), каждые четыре звучащих такта или конец маршрута. Фигура заменяет обычные ударные последнего пульса и помечена `fill: 'transition' | 'phrase' | 'ending'`. Она допускается только при полной звучащей гармонии этого пульса и непустом начале следующего такта; паузы исключаются. У финального пульса круга бас и клавиши получают `ending: true`, синхронный акцент в начале своего сегмента и укороченную длительность. Это окончание круга, а не дополнительный такт и не изменение длительности формы.

Фигуры — собственные короткие последовательности kick/snare/hat, в точных долях последнего пульса. Сбивка не меняет транспорт, тактовые позиции и ключевые границы тренировки. Реверберация и время жизни источников используют те же ограничения, что обычные события.
